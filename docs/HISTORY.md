- [x] Agent 自查历史会话 + 回滚备注（据「让 agent 查它自己过去的 session 记录、回溯改动，可能要回滚的把改动前的数值写在备注上」需求）：
  - **两个新 MCP 工具**：`list_sessions`（查自己过去的会话，可按 `since`/`until` 日期、`keyword`（同时匹配会话名/简介/**该会话跑过的 SQL**）、`project`/`connection`、`writes_only` 筛选；默认只列**当前 agent 自己的**，`all_agents=True` 才看别人的）→ `session_history(session_id)`（看那次会话的操作，最近在前）。
  - **审批单新增 `rollback_note` 字段**（正是用户问的「要不要在审批记录中增加一个字段」——要）：`execute(..., rollback_note="改前 1001.status=2；回滚 UPDATE ...")` 存进审批单，**审批人在审批页看得到**（新增「回滚参考」栏，判断可回滚性），事后 agent 用 `session_history` 取回来拼回滚 SQL（回滚照样走审批）。老库自动 ALTER 补列。
  - **审计记录加 `change_id` 列**关联回审批单——否则「这条写操作对应哪张单/备注在哪」只能去 `detail` 文本里正则抠。首提、核销执行、sync 三处都写上；老库自动 ALTER。
  - **结果状态筛选**（据反馈「能够查状态吗？比如只查允许并执行成功的」）：两个工具都加 `status`（ok/rejected/error，非法值报错不静默返空）。**关键语义**：写操作首提生成审批单那条审计记录是 `rejected`（没落库），真正执行的那条才是 `ok`——所以「真正改成过数据」= `writes_only=True, status="ok"`，不加 status 会把两条都带出来。`list_sessions` 的 status 是行级过滤（ops/writes 只数符合的操作）；`session_history` 额外返回 `status_counts` 让 agent 一眼看出还有没有被挡下/出错的。
  - **`rollback_note` 明确是「建议」不是强制**（据反馈「这个只能是建议，agent 自己判定这次改动有没有回溯的必要」）：MCP instructions 与工具描述都写成「你自己判断有无回滚价值，无关紧要的改动留空即可」，不做任何服务端强制。
  - **`session_history` 默认不返回 SQL 原文与错误明细**（据反馈「sql、结果这些太大了，不要默认给」）：默认精简列 = ts/tool/connection/status/row_count/change_id/approval_status/rollback_note，`fields="sql,detail"` 或 `fields="all"` 才给；未点名 sql 时返回里带 `hint` 教怎么取。空值列直接省掉不占位。SQL 超 2000 字截断。
  - **日期过滤按本地时区解释**（`parse_time_filter`）：`audit_log.ts` 存 UTC，而人和 agent 说的「2026-09-08」是本地日期，直接比会整体偏一个时区（东八区漏掉当天早 8 点前的记录）。只给日期补本地零点/当天 23:59:59.999 再转 UTC；带偏移的按自身时区转。
  - **keyword 命中 SQL 用相关子查询而非直接进 WHERE**：直接过滤会让 `ops`/`writes` 只数到「含关键词的那几条」，与「这个会话有多大」的语义不符；而 project/connection 筛选**有意**采用行级过滤（「我在这个库上做过什么」的自然语义就是只统计该连接上的操作）。
